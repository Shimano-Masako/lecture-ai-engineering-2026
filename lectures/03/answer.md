# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：素のLLMはツールを持たずに直接回答するため、講座固有の「3レベル」について「分からない」と答えるか、一般論で誤った回答をする可能性がある。一方、エージェントは `search_glossary` で用語集を検索してから回答するため、講座で定義された正しい内容を返せる。
- `--trace` で見えたツール呼び出し（ツール名と引数）：search_glossary({'query': 'QLoRA'})
- 1つの質問での LLM 呼び出し回数（`requests`）：2
- 追加したツールと、docstring に書いた説明：`make_quiz(lecture: int)` を追加した。指定した回の学習後に、用語の意味を確認する問題と答えを1問作るツールで、講義内容の理解を確認したいときや、学習者に小テストを出すときに使う。

## 宿題

- 取り組んだレベル：基礎
- やったこと：同じ質問「第2回の内容から確認問題を1問出して」に対して、まず通常の `INSTRUCTIONS` で `uv run python -m app.agent --trace` を実行した。その後、`app/agent.py` の「用語や講座に固有のことを答える前に、必ず search_glossary で用語集を確認する。」という1行だけを削除して、同じ質問をもう一度実行した。
- 結果：通常は `make_quiz({'lecture': 2})` が1回呼ばれ、`requests=2` だった。検索指示を弱めても同じツール呼び出しと `requests=2` になったが、通常は問題だけを返したのに対し、変更後は事前学習についてのヒントを付けた詳しい回答になった。今回は `make_quiz` の docstring に確認問題を作る用途が書かれていたため、検索指示を弱めてもこのツールの利用は変わらなかった。
- 気づき・疑問：`INSTRUCTIONS` はツールを使う順序や条件に直接影響し、docstring はモデルに見えるツールの用途説明として呼び出し判断に影響する。同じ質問でもモデルの確率的な判断で結果が揺れるため、1回の実行だけでなく複数回比較するとより確実に差を確認できる。
